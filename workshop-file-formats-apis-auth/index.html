  • Carries formulas and charts, not just values
  • A heavy-duty version of a .csv

01 // Binary Formats

  • Also binary, but built to never change
  • Looks the same on every device and every app
  • A frozen printout: great for sharing, hard to edit

02 // Section Two

APIs & MCPs

How software talks to other software, the integration mess that created, and the standard that fixed it.

fiba labs

02 // The Foundation

What Is an API? The Waiter Analogy

  • You (the app) ask the waiter (the API)
  • The waiter carries your request to the kitchen (the server) and brings the answer back
  • GET = bring me, POST = place an order, SELECT = what's on the menu
fiba labs

02 // The Problem

Scene 1: Every Kitchen, Its Own Language

  • Each service (GitHub, Stripe, Postgres) speaks its own dialect
  • Your AI has to learn every one of them, separately
  • Many tools × many services = a custom-integration mess
fiba labs

02 // A Partial Fix

Scene 2: Coding Assistants Are Faster, Still Rigid

  • AI can write the integration code for you, cheaply
  • But the result is still hard-wired and brittle
  • Cheaper to build, but the mess doesn't go away
fiba labs

02 // Same Problem, Shipping Analogy

Break-Bulk World: Every Factory Packs Differently

  • Before shipping containers, every factory packed its own way
  • Every dock had to learn every factory
  • The exact same many×many training problem
fiba labs

02 // The Insight

The Container Era: Wrap It Once

  • The container standardized the box, the cargo didn't change
  • The API is still inside, just wrapped in a standard shell
  • Factory wraps once, the whole world can handle it
fiba labs

02 // The Payoff

Scene 3: The MCP World

  • MCP is the container for AI tools
  • Your AI speaks one language and asks each tool live: "what do you offer?"
  • Build once, connect everywhere
This is why your AI can suddenly talk to Gmail, your CRM, your calendar

03 // Section Three

Authentication Methods

How an app proves who you are and what it's allowed to do, explained with everyday objects.

fiba labs

03 // Overview

Five Ways to Prove Who You Are

  • API key (a key), token (a wristband), JWT (a signed badge)
  • Session+cookie (a coat-check stub), OAuth (a hotel keycard)
  • Two questions: who are you? (authentication) and what can you do? (authorization)
fiba labs

03 // The Detail

How Each One Actually Works

  • Key: one secret, no expiry — if leaked, it works forever
  • Badge/JWT: carries its own info, no lookup needed
  • OAuth: scoped, expiring, revocable, your password never shared
fiba labs

03 // The Flow You Already Use

How OAuth Works: "Sign in with Google"

  • You approve at the provider (Google), not the app
  • The app gets a limited token, never your password
  • You can revoke it anytime
When an app bounces you to a Google approval screen, that's OAuth, the safe one
