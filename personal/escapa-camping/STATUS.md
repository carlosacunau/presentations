## Key decisions
- One source of truth. `poleras.html` reads the same `DATA` as `matrix.html`; a
  second tab in Sheets would have been a second, worse answer (431 vs 426 at the time).
- Only duplicate ENTRIES get removed, never multi-camp parents. Each camp has its
  own logo and sometimes its own color, so a parent in N camps gets N shirts.
- Kids get exactly one shirt, for the camp they attend. Papimono is the only camp
  that admits younger siblings; the rest take only the kid in that grade
  (twins and triplets are fine, same level).
- Shirts without a size are still counted in the print total, because they will be
  printed. The counter exists to drive that number to zero, not to hide them.
- `sync.py` dedupes on the normalized parent name (accents and case stripped). It
  cannot catch a duplicate where a surname was added on the second submission
  (Jensen / Jensen Diblase). Carlos fixed those by hand in the sheet instead of
  adding phone-based dedup; revisit only if it happens again.
- Never touch "Form Responses 1". The sync reads it, nothing writes to it.
  (260922: escribi la celda H184 con las tallas de las mellizas. Rompi la regla.
  De aqui en adelante le paso los valores a Carlos y el los escribe.)
- Las excepciones de doble campamento van en la constante `SEGUNDO_CAMPAMENTO`
  de sync.py, no en el sheet ni en el html. El sheet no puede expresar "este hijo
  va a dos campamentos" y el html no debe mostrarlo. Hoy solo aplica a Borja.
- Las tallas faltantes se guardan como "—" (guion largo), NO como string vacio.
  Cualquier conteo que pregunte `if not talla` devuelve 0 faltantes y es un
  falso negativo. Hay que comparar contra el placeholder.

## Gotchas de publicacion
- El commit del sync NO dispara el deploy de Pages. Despues de correr
  `gh workflow run sync-camping.yml` hay que correr tambien
  `gh workflow run 232347981` (Deploy to GitHub Pages) o la pagina queda vieja.
- `git push` no es publicar. Verificar con `gh run watch <id> --exit-status`
  y luego leer la URL con cache-buster.
- Al verificar con curl, usar `curl -o archivo` y NO `curl > archivo`:
  la redireccion devolvia 1.253 bytes (truncado) y me hizo diagnosticar mal
  una pagina que en realidad estaba bien.
