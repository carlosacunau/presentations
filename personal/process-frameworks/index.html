03 // framework
Cadena de Valor
Porter · 1985

Cadena de Valor

Descompone a la empresa en actividades que generan valor y un margen final. Separa actividades primarias (flujo operativo) de actividades de apoyo (transversales).

Cuándo usarloAl inicio del diagnóstico. Responde dónde está el valor y dónde están los costos.
EjemploUna distribuidora identifica que Logística externa y Servicio concentran 70% del costo, y prioriza ahí cualquier iniciativa de automatización.
04 // framework
SIPOC
Six Sigma · delimitación

SIPOC

Herramienta de delimitación que describe un proceso en 5 columnas: Suppliers (proveedores), Inputs (insumos), Process (proceso), Outputs (salidas), Customers (clientes).

Cuándo usarloJusto después de Porter, para acotar el proceso específico que se va a intervenir. Es el paso previo obligado antes del BPMN.
EjemploProceso de reembolsos: Suppliers=agencias, Inputs=solicitud, Process=validación+aprobación+pago, Outputs=monto acreditado, Customers=pasajero.
05 // framework
BPMN 2.0
OMG · 2011

BPMN 2.0

Estándar internacional para diagramar procesos con notación visual precisa y ejecutable. Eventos, actividades, compuertas y carriles.

Cuándo usarloCuando el proceso delimitado con SIPOC necesita representarse en detalle para optimizarlo o automatizarlo.
EjemploUn BPMN del onboarding revela que la validación de identidad es el cuello de botella, no el contrato.
06 // framework
AS-IS / TO-BE
Gap analysis

AS-IS / TO-BE

Comparación entre el estado actual del proceso (AS-IS) y el estado objetivo (TO-BE), con la brecha entre ambos.

Cuándo usarloDespués del BPMN del proceso actual. Fuerza a definir qué se quiere lograr antes de pensar en herramientas.
EjemploAS-IS tiene 12 pasos manuales, TO-BE tiene 4 pasos con 2 automáticos. Brecha: 60% menos tiempo.
07 // framework
PDCA / PHVA
Deming · 1950s

Ciclo PDCA

Ciclo iterativo de mejora continua: Plan, Do, Check, Act. En español: Planificar, Hacer, Verificar, Actuar (PHVA).

Cuándo usarloComo marco iterativo una vez que el proceso está en operación. Es la lógica de fondo de cualquier mejora continua.
EjemploPiloto de un chatbot en un solo canal (Do), se mide tasa de resolución (Check), si supera el 70% se extiende (Act).
08 // framework
DMAIC
Six Sigma · 1986

DMAIC

Metodología estructurada de 5 fases: Define, Measure, Analyze, Improve, Control. Más rigurosa que PDCA, exige datos en cada fase.

Reframe claveDMAIC no es solo una metodología de mejora: es un filtro de rechazo. Si el proceso no supera Define + Measure, no debería automatizarse.
EjemploAntes de automatizar la facturación, DMAIC revela que 40% de los errores vienen de datos mal cargados. Se arregla el input primero.
09 // framework
Impacto vs. Esfuerzo
Matriz de priorización

Impacto vs. Esfuerzo

Matriz 2×2 para priorizar iniciativas según el impacto esperado y el esfuerzo requerido.

Cuándo usarloAl cierre del diagnóstico, cuando hay una lista larga de oportunidades y hay que decidir por cuál empezar.
EjemploAutomatizar el envío de confirmaciones de email (ganancia rápida) antes que rediseñar el CRM completo (proyecto mayor).
10 // framework
Kotter
Gestión del cambio · 1996

Modelo de Kotter

Ocho pasos secuenciales para que una transformación organizacional arraigue.

Cuándo usarloCuando la automatización toca personas, roles o hábitos. Sin Kotter (o equivalente), el proceso queda en piloto permanente.
EjemploLanzar con un equipo piloto (paso 5), medir a 30 días (paso 6), replicar al resto con los casos de éxito a la mano (paso 7).
