Technical Architecture — How It Actually Works

FibaLabs Managed AI OS · Message Flow & System Architecture

Subscription-first: CLI online = free. CLI offline = Haiku (cheap) or queue.
Customer installs 2 things: Discord + Claude Code CLI. That's it.
VPS is the 24/7 backbone. It never sleeps.
Customer Zone
💬 Discord App
Phone + Laptop. Customer's only interface. Sends messages, receives responses, gets daily briefs.
⚡ Claude Code CLI daemon
Runs in background on customer's laptop. Invisible after onboarding.
Auto-starts on login (LaunchAgent / systemd)
Heartbeat to VPS every ~30s
Full local access to files, repos, tools
Handles ALL tasks when online — simple or complex
$0 API cost Uses Claude subscription
Customer never interacts with CLI directly. Discord is the only surface.
VPS Zone — 24/7 Backbone
🤖 GoBot — Discord Gateway
Captures all Discord messages. Webhook processor. Multi-customer adapter.
Message Router — Subscription-First Logic
Message arrives at VPS │ ├── CLI online? (fresh heartbeat) │ └── YES → Route to CLI │ $0 Subscription, zero API cost │ CLI has full local file access │ Handles ALL tasks: simple or complex │ └── CLI offline? (stale heartbeat) ├── Simple enough for Haiku? │ └── YES → Process with Haiku API │ ~$0.001 Cheap, immediate │ └── Complex task? └── Queue in Supabase queued Until CLI comes back
Supabase — Per-Customer Data (RLS Isolation)
messages memory async_tasks node_heartbeat call_transcripts metrics assets (Storage)

Key Data Flows
1
Customer message → Discord → VPS (GoBot captures) → Router decides: CLI, Haiku, or queue
2
CLI processes task → Result sent back to VPS → GoBot posts response in Discord
3
Scheduled jobs run on VPS → Results stored in Supabase → GoBot pushes daily brief to Discord
4
Carlos pushes code → VPS auto-deploys via webhook → Customer gets update instantly
