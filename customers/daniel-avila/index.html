Situación actual

El proceso
manual de hoy

Flujo de cotización

Cinco pasos, todos manuales

  1. Cliente envía patente por WhatsApp
  2. Entrar al sitio del proveedor, ingresar la patente
  3. Identificar el producto correcto (pastilla delantera / trasera, marca, calidad)
  4. Consultar cotizador propio en planilla para obtener precio de venta
  5. Escribir manualmente la respuesta al cliente por WhatsApp
El costo real

Tiempo y ventas perdidas

2 min por cotización individual

= venta
perdida si no respondes primero

"El cliente manda el mismo mensaje a varios talleres. El primero que responde, se lleva la venta."

Casos complejos

No siempre es directo

  • Una patente puede devolver dos pastillas traseras diferentes (versión japonesa vs. india del mismo auto)
  • El listado no tiene orden fijo — hay que buscar manualmente la combinación correcta
  • Los precios del proveedor no son los precios de venta — requieren transformación (markup, ×2 para discos, etc.)

Cuando aparecen dos opciones, hay que mostrar las imágenes de cada pastilla al cliente para que confirme cuál corresponde a su auto.

Lo construido

03
Propuesta

La solución
en dos fases

Arquitectura general

Cuatro piezas que trabajan juntas

🗄️

Base de datos offline

Todos los productos del proveedor scrapeados y almacenados localmente. Se actualiza periódicamente, no en tiempo real.

🔗

Cruce patente → auto

Base de patentes chilenas vinculada a marca / modelo / año / cilindrada para identificar el auto del cliente.

🤖

Bot WhatsApp

Recibe la patente, consulta la base de datos y devuelve la cotización con precio de venta calculado.

🖼️

Imágenes on-demand

Cuando hay dos opciones, descarga y envía las imágenes para que el cliente confirme cuál corresponde.

Fase 1

Web scraping de la base de datos

  • ~383 páginas de productos en el sitio del proveedor
  • Estimado de 50.000+ registros (5.000 por marca × ~10 marcas)
  • Cada producto incluye SKU, código de pastilla, modelos compatibles y precio
  • Las imágenes no se descargan en bloque — se obtienen solo cuando hay ambigüedad
  • El scraping se corre en servidor una vez cada 3–6 meses para mantener la base al día

Opciones técnicas

  • APIFY — actores en la nube, pago por uso
  • Script propio en servidor — control total, costo fijo

Scrapear offline es mejor que hacerlo en tiempo real: más estable, sin riesgo de ser bloqueado en cada consulta del cliente.

Fase 2

Bot de cotización en WhatsApp

Flujo automatizado

  1. Cliente envía patente por WhatsApp
  2. Bot consulta base de patentes → obtiene marca / modelo / año
  3. Bot consulta base de productos → encuentra pastillas disponibles
  4. Aplica markup configurado → calcula precio de venta
  5. Envía cotización formateada al cliente

Casos especiales

  • Dos opciones detectadas → envía imágenes y pide confirmación
  • Patente no encontrada → solicita marca / modelo / año manualmente
  • Producto fuera de catálogo → deriva al humano
WhatsApp Business API Respuesta < 30 seg
Enfoque modular

Evolución por bloques

Cada bloque entrega valor independiente. No se paga el siguiente hasta que el anterior funciona.

Bloque 1 — Base de datos de productos

Scraping del sitio del proveedor. Resultado: tabla limpia con SKU, código, modelos compatibles, precio proveedor.

Bloque 2 — Cotizador automático

Bot WhatsApp que recibe una patente y devuelve la cotización con precio de venta calculado.

Bloque 3 — Manejo de ambigüedad

Lógica para detectar múltiples opciones, enviar imágenes y confirmar con el cliente.

Bloque 4 — Integración de inventario

El bot indica si el producto está en stock local antes de cotizar al cliente.

Bloque 5 — Despacho automático (futuro)

Si hay stock, notifica al repartidor. Si no, genera orden al proveedor directamente.
